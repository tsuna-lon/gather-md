# レポート自動集約・リアルタイム生成ツール (gather-md)

本ツールは、章ごと・設問ごとに分割執筆したMarkdownファイルから、レポート本文（指定のコードブロック）を自動抽出し、あらかじめ用意したひな型（テンプレート）へ流し込んで、1つの完成レポートをリアルタイムに自動生成・更新するPythonスクリプトです。

ObsidianなどのMarkdownエディタと併用することで、下書きやメモ・参考文献を自由に書きながら、常に最新の完成原稿と文字数を確認できます。

---

## 主な機能・特徴

1. **複数プロジェクト（マルチスコープ）の自動認識**
   * 「レポート課題」ディレクトリ配下の全サブディレクトリを監視します。
   * 各課題フォルダに「定義ファイル」を配置するだけで、フォルダごとに独立したルールで完成レポートが出力されます。
   * 下書きファイルを保存すると、そのファイルが属するフォルダの定義ファイルを自動的に特定して更新します。
2. **2つの定義ファイル形式に対応**
   * **`_template.md`**: テンプレートそのものをMarkdownとして作成し、先頭にメタデータ（フロントマター）を書く方式（Obsidianで扱いやすくおすすめ）。
   * **`report_config.yaml`**: YAML設定ファイル内でテンプレート文字列や外部テンプレートファイルを指定する方式。
3. **柔軟なタグ・識別子記法**
   * **下書き側**: ````report:タグ名```` で本文を囲むだけ。英数字だけでなく、日本語タグ（例: ````report:１．はじめに```` や ````report:設問1````）やスペース入り（````report: intro````）にも対応。
   * **ひな型側**: `<!-- INSERT:タグ名 -->`（Markdownプレビューで目立たないHTMLコメント）および `{{タグ名}}`（シンプルな二重中括弧）の両方に対応。
4. **未作成・未記入ブロックの注記残し**
   * 該当タグが存在しない場合は `【未作成: タグ名】`、コードブロックはあるものの本文が空（または空白・改行のみ）の場合は `【未記入: タグ名】` として出力され、タグの指定ミスか執筆進捗かが一目でわかります。
5. **文字数の自動集計・埋め込み**
   * 大学レポートで重要な「文字数カウント」を自動集計します。
   * `{{char_count}}` または `<!-- CHAR_COUNT -->` と記述しておくだけで、空白・改行や未作成・未記入ラベルを除外した純粋な本文文字数をリアルタイムに置換します。
6. **安全な監視・更新**
   * 出力ファイル（完成レポート）自身の書き換えによる無限ループを自動防止。
   * エディタ保存時の連続イベントをデバウンス（間引き）処理し、安定して動作します。
7. **新規課題フォルダのテンプレート自動生成**
   * 本アプリ起動中に、監視ルート直下へ新規フォルダ（例: `経済学`）を作成すると、自動的に初期テンプレート（`_template.md`）と初期レポートが生成されます。
   * 監視ルートから見てサブディレクトリにあたる階層（各課題フォルダ内の `下書き/` や `images/` など）が作成されても、テンプレートの自動生成は行われません。
   * すでにテンプレートや定義ファイルが存在する場合は上書きせずスキップします。
8. **完成レポートの誤編集防止（警告バナー＆自動ロールバック復元）**
   * 自動生成された完成レポートをエディタで誤って直接編集してしまい、次回更新時に上書き消失してしまう事故を防ぎます。
   * **警告バナー（Callout記法）**: レポート先頭に注意を促すバナーを自動挿入（本文の文字数集計には影響しません）。
   * **自動ロールバック復元**: 完成レポートがエディタ上で直接編集・保存された場合、スクリプトが即座に下書きから正規の内容へ再生成して自動復元します。
   * **エディタとの親和性**: Obsidian等のエディタでファイル切り替え時に発生する自動保存エラー（スタック現象）を回避するため、OSの属性ロックに依存しない安全な保護を提供します（必要に応じて `readonly: true` によるOS属性ロックも利用可能）。
9. **二重起動防止機能 (Single Instance)**
   * Windowsの名前付きミューテックスにより、同一ディレクトリでの多重起動を自動防止します。
   * 誤って二重起動した場合は、デスクトップ通知と警告ログを出力して即座に終了します（別フォルダでの同時実行は可能）。
10. **Windows デスクトップ通知 (トースト通知)**
    * スクリプトの起動時、Obsidian検出時、終了時（正常終了・Obsidian連動終了・エラー停止）、二重起動検知時にWindows標準のトースト通知でお知らせします。
    * 外部ライブラリを必要とせず、Python標準機能のみで動作します。
11. **Obsidian 連動ライフサイクル管理（自動終了・複数書庫対応）**
    * 開いているObsidianの書庫（Vault）ウィンドウを自動検出します。
    * 起動時に対象書庫が開いていない場合でも「待機モード」として監視を開始し、Obsidianが開かれたタイミングで自動連動を開始します。
    * 対象の書庫ウィンドウが閉じられた場合、スクリプトも自動的に安全終了します。
    * 複数の書庫（Vault）を同時に開いている場合でも、監視ディレクトリに対応する書庫ウィンドウのみをピンポイントで判別するため、他の書庫の作業に影響を与えません。
12. **コードブロック自動出力（Doc貼り付け・印刷用表示分離）**
    * フロントマターや設定で `code_block: true` を指定するだけで、本文プレースホルダー領域を自動的にコードブロック（` ```text ... ``` `）で囲んで出力します。
    * 段落初めの字下げ（全角スペース）やインデント、改行が崩れず100%保持され、ブラウザDoc等へ貼り付けて印刷する原稿作成に最適です。
    * **警告バナーとの表示分離**: 誤編集防止警告バナー（`> [!CAUTION]`）や見出し・文字数フッターはコードブロックの外側に配置されるため、Obsidian上でコードブロック右上の「コピー」ボタンを押すだけで、余計な注意書きや文字数情報を含まない**「本文テキストだけ」をワンクリックでコピー**できます。
    * **文字数の正確な集計**: コードブロック開始・終了行（` ```text ` や ` ``` ` 等）やバッククォート記号は文字数集計から自動除外されるため、本文の正確な文字数が表示されます。

## 必要な環境・ライブラリ

Python 3.10 以上

必要な外部ライブラリ:

* `watchdog` (ファイル監視用)
* `PyYAML` (YAML/Frontmatter解析用)

```bash
pip install watchdog pyyaml
```

## 使い方

### 1. 監視の開始

ターミナルまたはPowerShellで、**監視ルートディレクトリ** に移動してスクリプトを実行します。

```bash
python gather_md.py
```

* 起動時に、同一フォルダでの二重起動チェックを行い、配下の全フォルダから定義ファイルを自動検出し、初回ビルド（全レポートの更新）を行います。
* 起動時に対象のObsidian書庫（Vault）が開かれていない場合は、トースト通知でお知らせした上で待機モードに入り、Obsidian起動時に自動連動します。
* 終了する場合は、対象のObsidian書庫ウィンドウを閉じるか、コンソールで `Ctrl + C` を押します。

## 定義ファイルの書き方

各レポートのフォルダ（例: `情報社会論`）の直下に、以下のいずれかの定義ファイルを配置します。

### 方式A: `_template.md` を使う場合（推奨）

フォルダ直下に `_template.md` を作成します。
先頭にFrontmatter（`---` で囲まれた設定）を記述し、その後にレポートのひな型を書きます。

```markdown
---
output: "_完成レポート.md"
readonly: false
warning_banner: true
auto_rollback: true
code_block: false
---
# 情報社会論 レポート

{{１．はじめに}}

{{２．背景と課題}}

{{３．今後の展望}}

---
文字数: {{char_count}} 字（空白含: {{char_count_with_spaces}} 字）
```

> **Note**: 先頭の `---`（Frontmatter）を省略した場合は、自動的に `_完成レポート.md` というファイル名で出力され、誤編集防止機能（警告バナー挿入、自動ロールバック復元）が適用されます。
>
> **Tip**: 完成レポートに `<!-- END:... -->` などのコメントタグを残さず本文のみを出力したい場合は、`<!-- INSERT:１．はじめに -->` の代わりに `{{１．はじめに}}` と記述してください（詳細は後述の「プレースホルダー一覧」を参照）。
>
> **Tip (印刷・Doc貼り付け用)**: ブラウザDoc等に貼り付けて印刷する用途で、段落はじめの字下げ（全角スペース）を完全に保持して本文だけをコピーしたい場合は、`code_block: true` を指定してください。

### 方式B: `report_config.yaml` を使う場合

フォルダ直下に `report_config.yaml` を作成します。

```yaml
output: "_完成レポート.md"
readonly: false
warning_banner: true
auto_rollback: true
code_block: false

template: |
  # 情報社会論 レポート

  {{１．はじめに}}

  {{２．背景と課題}}

  {{３．今後の展望}}

  ---
  文字数: {{char_count}} 字
```

別ファイルのテンプレート（例: `my_template.md`）を読み込ませたい場合は、以下のように記述します:

```yaml
output: "_完成レポート.md"
readonly: false
warning_banner: true
auto_rollback: true
code_block: false
template_file: "my_template.md"
```

### 設定オプション一覧（Frontmatter / YAML 共通）

| 設定項目 | 型 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| `output` | 文字列 | `"_完成レポート.md"` | 出力先レポートのファイル名。 |
| `code_block` | 真偽値 | `false` | 本文プレースホルダー領域を自動的にコードブロック（` ```text ... ``` `）で囲んで出力します。段落初めの字下げや改行が保持され、Obsidianのコードコピーボタンから本文のみをワンクリックコピーできます。 |
| `warning_banner` | 真偽値 | `true` | レポート先頭に自動生成ファイルである旨の注意喚起バナー（Obsidian Callout記法）を自動挿入します。本文の文字数カウントには影響しません。 |
| `auto_rollback` | 真偽値 | `true` | 完成レポートがエディタ上で直接編集された場合、下書きとテンプレートから即座に自動復元（ロールバック）します。 |
| `readonly` | 真偽値 | `false` | 完成レポートをOSの読み取り専用属性に設定します。Obsidian等のエディタでは保存失敗エラー（スタック現象）の原因となるため、通常は `false` を推奨します。`false` に設定されている場合、既存ファイルの読み取り専用ロックも自動解除されます。 |

> **保護設定のカスタマイズ**:
> 警告バナーが不要な場合は `warning_banner: false`、完成レポートを直接編集したまま維持したい場合は `auto_rollback: false` を指定してください。

## 下書きファイルの書き方

定義ファイルが置かれたディレクトリ配下であれば、どのサブフォルダ（例: `下書き/` や `章別/`）に置かれた `.md` ファイルでも自動的に読み込まれます。

コードブロックに `report:タグ名` を指定して本文を記述します。
コードブロックの外に書いたメモや参考文献などは、完成レポートには取り込まれません。
段落初めの全角スペース（`　`）や字下げインデントはそのまま維持されて完成レポートに出力されます（ブロック前後の余分な空行のみが自動除去されます）。

**例: `下書き/１．はじめに.md`**

````markdown
# 下書き用メモ
* 提出締切: 10月末
* 調査メモ: 最新の利用動向データを引用すること

```report:１．はじめに
１．はじめに
　近年、情報通信技術の急速な進展に伴い、私たちの生活や働き方は大きく変化している。特に生成AIをはじめとする新しい技術の普及は、利便性の向上をもたらす一方で、情報倫理や著作権保護といった新たな課題も生み出している。
　本レポートでは、情報社会における技術の利活用と、それに伴う倫理的課題について考察する。
```

## 参考文献

* 総務省 「情報通信白書」
* 情報 太郎 『情報倫理入門』 ○○出版, 2023年

````

## テンプレートで使用できるプレースホルダー一覧

| プレースホルダー | 説明 | 出力例 |
| :--- | :--- | :--- |
| `<!-- INSERT:タグ名 -->` | コメント形式（前後にマーカータグを残す） | `<!-- INSERT:タグ名 -->\n本文\n<!-- END:タグ名 -->` |
| `{{タグ名}}` | マスタッシュ形式（マーカーを残さず本文のみ展開） | `本文` |
| `{{char_count}}` | 空白・改行・HTMLコメント・未作成/未記入ラベルを除外した純文字数（カンマ付き） | `2,450` |
| `{{char_count_with_spaces}}` | 改行のみ除外した文字数（空白を含む、カンマ付き） | `2,680` |
| `{{char_count_raw}}` | 純文字数（カンマなし数値） | `2450` |
| `<!-- CHAR_COUNT -->` | 文字数カウントのHTMLコメント記法 | `2,450` |

※ 下書きに存在しないタグは `【未作成: タグ名】`、下書きに枠はあるが中身が空の場合は `【未記入: タグ名】` に置換されます（これらの注記ラベルは文字数カウントから自動除外されます）。

### コメントタグを残さないクリーンな出力を行いたい場合

完成レポート（`_完成レポート.md`）に `<!-- INSERT:... -->` や `<!-- END:... -->` のようなコメントタグを出力したくない場合は、テンプレート側で **`{{タグ名}}`（マスタッシュ形式）** を使用してください。

* **`{{タグ名}}` を使用した場合**:
  完成ファイルにはマーカーコメントが一切含まれず、本文のみが展開されます。提出用原稿や余計なコメントのないクリーンなMarkdown原稿を作成したい場合に適しています。
* **`<!-- INSERT:タグ名 -->` を使用した場合**:
  完成ファイルにも `<!-- INSERT:タグ名 -->` と `<!-- END:タグ名 -->` がマーカーとして出力されます。テンプレート作成時にエディタのプレビューでタグ自体を非表示にしたい場合や、完成ファイル側でも章や設問の境界を視覚的・構造的に識別したい場合に便利です。

## フォルダ構成の例

```text
レポート課題/
├── gather_md.py              # 監視スクリプト（ルートに配置）
├── README.md                 # 本説明書
│
├── 課題1 - 情報社会論/
│   ├── _template.md          # この課題用のひな型・定義ファイル
│   ├── _完成レポート.md       # 自動生成される完成原稿
│   └── 下書き/
│       ├── １．はじめに.md    # ```report:１．はじめに ... ```
│       ├── ２．背景と課題.md  # ```report:２．背景と課題 ... ```
│       └── ３．今後の展望.md  # ```report:３．今後の展望 ... ```
│
└── 課題2 - 環境と社会/
    ├── report_config.yaml    # YAML形式で定義することも可能
    ├── _完成レポート.md       # 自動生成される完成原稿
    └── 1-はじめに.md          # ```report:1-はじめに ... ```
```

## 注意事項

* **タグ名の重複**: 1つのプロジェクトフォルダ内で同一のタグ名が複数ファイルに存在する場合、後から読み込まれたファイルの内容で上書きされ、コンソールに注意ログが表示されます。
* **除外対象**: `.obsidian` や `.git` などのドットから始まる隠しフォルダ内のファイル、および出力先レポートファイル自身は自動的に収集・監視から除外されます。
* **文字コード**: Markdownファイルおよび設定ファイルは `UTF-8` で作成・保存してください。

# gather-md 仕様書

## 1. 目的

分割執筆されたMarkdownファイルから指定のコードブロックを抽出し、テンプレートに流し込んで1つの完成レポートを自動生成・リアルタイム更新するツール。
Obsidian等のMarkdownエディタと併用し、下書きやメモを残しながら完成原稿と文字数を即座に確認できる環境を提供する。

---

## 2. 前提条件・環境

* **言語**: Python 3.10 以上
* **依存ライブラリ**:
  * `watchdog`: ファイルシステム監視
  * `PyYAML`: YAML設定・Frontmatterパース
* **文字コード**: UTF-8

---

## 3. システム構成・ディレクトリ設計

```text
WATCH_ROOT/ (スクリプト配置ディレクトリ)
├── gather_md.py              # メイン監視・生成スクリプト
├── README.md                 # ユーザーマニュアル
├── .doc/
│   └── spec.md               # 仕様書（本書）
└── [課題フォルダ]/            # 各プロジェクトフォルダ（第1階層）
    ├── _template.md          # テンプレート定義ファイル（推奨）または report_config.yaml
    ├── _完成レポート.md       # 自動生成される出力ファイル
    └── [サブディレクトリ]/    # 下書きフォルダ（第2階層以降）
        ├── 1_はじめに.md
        └── 2_本文.md
```

---

## 4. 処理仕様

### 4.1. 監視対象とスコープ認識

* **監視ルート**: `gather_md.py` の存在するディレクトリ（`WATCH_ROOT`）。
* **プロジェクトの特定**:
  * 変更されたファイルから親ディレクトリを遡り、最初に見つかった定義ファイル（`report_config.yaml` / `report_config.yml` / `_report.yaml` / `_report.yml` / `_template.md` / `report_template.md`）の置かれたフォルダをプロジェクトルートとする。
* **除外対象**:
  * ドットから始まる隠しファイル・フォルダ（`.git/`, `.obsidian/`, `.agents/` 等）。
  * キャッシュフォルダ（`__pycache__/` 等）。
  * 出力先ファイル自身（無限ループ防止）。

### 4.2. 新規フォルダ作成時のテンプレート自動生成

* **トリガー**:
  * 常駐監視中に、`WATCH_ROOT` の**直下（第1階層）**に新規ディレクトリが作成された場合（`on_created` または `on_moved`）。
* **サブディレクトリの除外**:
  * 直下以外のサブディレクトリ（第2階層以降、例: `課題1/images/` や `課題1/下書き/`）が作成された場合は、テンプレート生成を行わない。
* **一時フォルダ名の保留（Windows対応）**:
  * Windowsエクスプローラー新規作成時のデフォルト名（`新しいフォルダー`, `新規フォルダー`, `New folder`）の間は生成を保留し、フォルダ名が確定（リネーム: `on_moved`）された時点で生成を実行する。
* **上書き防止**:
  * すでに定義ファイル（`_template.md` や `report_config.yaml` など）が存在する場合は生成をスキップする。
* **生成内容**:
  * `_template.md` をUTF-8で生成。
  * タイトルには確定したフォルダ名（`# {folder_name} レポート`）を反映。
  * 生成直後に初期完成レポート（`_完成レポート.md`）もビルドする。

### 4.3. データ抽出仕様

* **対象ファイル**: プロジェクト配下の全 `.md` ファイル（出力ファイル・テンプレートファイル・隠しフォルダ内を除く）。
* **ブロック抽出記法**:
  * ````report:<タグ名> ...````
  * タグ名は英数字、日本語、全角記号、スペースを許容。
  * 本文が空のコードブロックや、空白・改行のみのブロックも抽出対象。
  * 同一タグが重複した場合は後読み込み優先とし、警告ログを出力。
* **空白・インデント処理**:
  * ブロック先頭の空行（改行のみ・空白のみ行）および末尾の空白・改行を除去。
  * 本文先頭行の行頭にある全角スペース（段落初めの字下げ）やインデント用空白は除去せず保持して出力。

### 4.4. テンプレート置換仕様

1. **コメント記法**:
   * `<!-- INSERT:タグ名 -->` または `<!-- INSERT:タグ名 -->...<!-- END:タグ名 -->`
   * 下書きの該当ブロック本文で置換され、`<!-- INSERT:タグ名 -->\n本文\n<!-- END:タグ名 -->` の形式で出力。
2. **マスタッシュ記法**:
   * `{{タグ名}}`
   * 下書きの該当ブロック本文で直接置換。
3. **未作成・未記入タグ**:
   * 下書きに存在しないタグは `【未作成: タグ名】` として出力。
   * 下書きにタグは存在するが、本文が空文字または空白・改行のみの場合は `【未記入: タグ名】` として出力。
4. **文字数カウント**:
   * 集計対象外: HTMLコメントタグ（`<!-- ... -->`）および未作成・未記入ラベル（`【未作成: ...】`, `【未記入: ...】`）。
   * `{{char_count}}` / `<!-- CHAR_COUNT -->`: 空白・改行・集計対象外を除外した純文字数（3桁カンマ付き）。
   * `{{char_count_with_spaces}}` / `<!-- CHAR_COUNT_WITH_SPACES -->`: 改行のみ除外した文字数（空白を含む、3桁カンマ付き）。
   * `{{char_count_raw}}`: 純文字数（カンマなし数値）。

### 4.5. 誤編集防止仕様（完成レポートの保護）

集約先の完成レポートをエディタ上で誤って直接編集し、次回更新で上書き消失してしまう事態を防止する。
Obsidian等のエディタにおける自動保存（ファイル切り替え時のバッファ書き出し等）との競合を防ぐため、OS属性ロックに依存せず、警告表示と自動復元（ロールバック）を標準とする。

1. **警告バナーの自動挿入 (`warning_banner`)**:
   * **デフォルト値**: `true`
   * レポート本文の先頭に、自動生成ファイルであることを示す警告バナー（Callout記法）を自動挿入。
   * 警告バナーは文字数集計（`char_count` 等）の実行後に付加されるため、本文の文字数カウントには影響しない。
   * 設定ファイルまたは Frontmatter で `warning_banner: false` を指定することで非表示に設定可能。
2. **自動復元・ロールバック機能 (`auto_rollback`)**:
   * **デフォルト値**: `true`
   * 完成レポートがエディタ上で直接編集・保存されたことを検知した場合、下書きとテンプレートから生成される正規のレポート内容と照合。
   * 差分が存在する場合、下書きから即座に再生成して元に戻す（上書きロールバック）処理を実行。
   * スクリプト自身の書き込みや、差分を伴わない保存イベントでは再書き込みを行わず、安全に無限ループを防止。
   * 設定ファイルまたは Frontmatter で `auto_rollback: false` を指定することで無効化可能。
3. **読み取り専用属性の設定 (`readonly`)**:
   * **デフォルト値**: `false`
   * `true` に設定した場合のみ、OSのファイル属性を「読み取り専用（Read-only）」に設定。
   * ※Obsidian等のエディタでは、ファイル切り替え時に自動保存が試行されて保存失敗エラー（画面遷移のスタック）が発生するため、通常は `false` を推奨。
   * `readonly: false` の場合、過去に読み取り専用属性が付与されていた既存ファイルであっても自動的に書き込み権限を回復（ロック解除）する。

### 4.6. プロセス制御とライフサイクル連携

1. **二重起動防止 (Single Instance Lock)**:
   * Windows APIの名前付きミューテックス（`CreateMutexW`）を利用。
   * 監視ルートディレクトリ（`WATCH_ROOT`）のパスハッシュに基づきミューテックス名を生成（`Local\gather_md_{hash}`）。
   * 同一ディレクトリでの二重起動を確実に検出し、トースト通知と警告を出力して即座に終了。
   * 別ディレクトリ・別Vaultに対するスクリプトの並行起動は妨げない。
   * プロセス異常終了・強制終了時もWindows OSによりミューテックスが自動破棄されるため、ロックファイルの消し忘れによる不具合が発生しない。
2. **Windows トースト通知**:
   * PowerShellのWinRT Toast APIを非同期スレッド（`subprocess.run`、タイムアウト5秒）で呼び出し、メイン処理を一切ブロックせずにデスクトップ通知を表示。
   * 外部Pythonライブラリに依存せず、標準ライブラリのみで完結。
   * 通知タイミング:
     * **起動時**: 監視開始（Obsidian連動中 または Obsidian待機中）
     * **二重起動検知時**: 既に起動している旨の警告と終了通知
     * **連動開始時**: 待機中に対象書庫が開かれた際の検出通知
     * **正常終了時**: Obsidian終了検知または手動中断（Ctrl+C）による停止通知
     * **異常終了時**: 予期せぬ例外発生による停止通知
3. **Obsidian 書庫（Vault）連動・自動終了（待機モード）**:
   * **書庫（Vault）名の特定**:
     * `WATCH_ROOT` から親ディレクトリを遡り、`.obsidian` フォルダが存在するディレクトリ名を「対象書庫名」として特定（見つからない場合は `WATCH_ROOT.name`）。
   * **ウィンドウタイトル監視**:
     * Obsidianは書庫ごとに `{ノート名} - {書庫名} - Obsidian vX.X.X` のタイトルを持つ。
     * Windows API（`EnumWindows`）および `tasklist` により、現在開いているObsidianウィンドウを定期スキャン（約2秒間隔）。
     * 複数書庫が開かれている場合でも、対象書庫のウィンドウのみをピンポイントで照合・識別。
   * **ライフサイクル同期（待機モード）**:
     * 起動時に対象書庫が開いていなくても監視を開始し、「起動待機中」として通知。
     * バックグラウンドで待機し、対象書庫が開かれた時点で連動状態へ遷移。
     * 連動中に対象書庫のウィンドウが閉じられた場合、一時的リロード等の誤検知防止（連続2回未検出）を経て、本プログラムも安全に自動終了する。

## 5. エラー処理・安全性

* **ファイルロック・連続イベント対策**:
  * 同一ファイルへの短時間の連続イベントはデバウンス（間引き: 0.3秒）処理。
* **内容一致チェック**:
  * レポート生成結果が既存ファイルと完全に一致する場合は書き込みをスキップし、ディスクI/Oと不要な再検知を抑止。
* **安全なパーミッション制御**:
  * 書き込みエラー時も可能な限り読み取り専用保護を再適用し、不整合を防止。
* **例外耐性**:
  * ファイル読み込み・パース失敗時は警告を出力し、全体の監視プロセスを停止させない。
